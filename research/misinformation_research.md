# Research Report: Misinformation Detection on Social Media

## Executive Summary
This report analyzes architectural approaches for a university project focused on "Misinformation Detection on Social Media." The project relies on a modern stack comprising Python (FastAPI) for the backend and HTML/CSS/JS (React.js) for the frontend. The research outlines three engaging sub-topics with readily available datasets (AI-generated misinformation, health myths, and crypto scams). It details two distinct architectural paths: a 'Safe' approach using manual text input and traditional Machine Learning (Scikit-learn), and a 'Hard' approach leveraging live social media scraping and Large Language Models (Transformers). Finally, it addresses critical risk mitigation strategies for both technical paths to ensure a robust and gradable project.

## Key Findings

### 1. Specific Sub-topics
Selecting a scoped sub-topic is critical for university projects. The following areas have robust, readily available datasets on platforms like Kaggle:

1. **AI-Generated Misinformation**:
   - **Focus**: Detecting synthetic text or images generated by LLMs (e.g., ChatGPT) and diffusion models (e.g., Midjourney).
   - **Datasets**: *Gen AI Misinformation Detection Data (2024–2025)* and *Misinfo-dataset* on Kaggle. These include simulations of news articles and social media posts labeled for AI generation.
   - **Why it's engaging**: Highly relevant to current events and allows for exploring patterns in synthetic text vs. human text.

2. **Health/Medical Myths (e.g., COVID-19, Vaccines, Home Remedies)**:
   - **Focus**: Classifying health claims as true, false, or mixed, based on medical consensus.
   - **Datasets**: *PUBHEALTH* (19k+ claims labeled by fact-checkers) and various *COVID-19 Fake News Datasets* containing social media posts.
   - **Why it's engaging**: Strong societal impact; text is often emotionally charged and features specific medical terminology.

3. **Financial and Crypto Scams**:
   - **Focus**: Identifying pump-and-dump schemes, fake airdrops, and fraudulent token promotions on social media (e.g., Twitter/X).
   - **Datasets**: *Financial Tweets Dataset* and specific *Crypto Tweets* datasets containing scam annotations.
   - **Why it's engaging**: Combines sentiment analysis with entity recognition (tracking specific coin tickers or URLs).

### 2. The 'Safe' Tech Stack & Architecture
This approach minimizes technical risk, ensuring a functional end-to-end prototype suitable for a university grading rubric.

*   **Frontend**: React.js (HTML/CSS/JS)
    *   **Architecture**: A simple Single Page Application (SPA). Users manually paste a suspicious social media post or news article into a text area and click "Analyze."
    *   **Libraries**: `axios` for API calls, `tailwindcss` for quick styling, `recharts` for displaying confidence scores.
*   **Backend**: Python with FastAPI
    *   **Architecture**: REST API with a `/predict` endpoint that receives text, preprocesses it, and passes it to a pre-trained ML model loaded in memory.
    *   **Libraries**: `scikit-learn` (for ML), `nltk` or `spaCy` (for text preprocessing - stemming, stop words), `uvicorn` (ASGI server).
*   **Machine Learning (Traditional ML)**:
    *   **Pipeline**: TF-IDF (Term Frequency-Inverse Document Frequency) Vectorizer followed by a Naive Bayes (MultinomialNB) or Logistic Regression classifier.
    *   **Workflow**: The model is trained offline in a Jupyter Notebook, exported using `joblib` or `pickle`, and loaded into the FastAPI application state on startup.

### 3. The 'Hard' Tech Stack & Architecture
This approach aims for high marks by incorporating real-time data ingestion and state-of-the-art Deep Learning models.

*   **Frontend**: React.js (HTML/CSS/JS)
    *   **Architecture**: Dashboard SPA. Instead of manual text input, users enter a social media handle, hashtag, or keyword. The UI streams live classification results and aggregates them into charts.
    *   **Libraries**: `react-query` or WebSocket connections (via `socket.io-client`) for real-time updates.
*   **Backend**: Python with FastAPI
    *   **Architecture**: Asynchronous REST API and WebSockets. A background task or Celery worker handles the slow scraping process, feeding text to the LLM and pushing results to the frontend.
    *   **Libraries**: `snscrape` (or its successor `twscrape`) / `Tweepy` (if using official Twitter/X API), `websockets`, `celery` + `redis` (for task queuing).
*   **Machine Learning (LLMs/Transformers)**:
    *   **Pipeline**: A fine-tuned Transformer model (e.g., RoBERTa, BERT, or DistilBERT) loaded via HuggingFace `transformers`.
    *   **Workflow**: Text is tokenized and passed through the Transformer for binary classification (Misinformation vs. Factual). The model runs on PyTorch.

### 4. Risk Mitigation

#### Handling Cloud RAM Limits for Large Models ('Hard' Stack)
*   **Risk**: Free or student-tier cloud providers (Render, Heroku, AWS EC2 Micro) typically offer 512MB - 1GB RAM. Loading a standard BERT model (~400MB) alongside FastAPI can cause out-of-memory (OOM) crashes.
*   **Mitigation**:
    1.  **Model Quantization**: Convert the PyTorch model to ONNX format or use dynamic quantization (`torch.quantization.quantize_dynamic`) to reduce the model size by up to 75% with minimal accuracy loss.
    2.  **Smaller Architectures**: Swap BERT for `DistilBERT` or `MobileBERT`.
    3.  **API Delegation**: Instead of hosting the model locally, deploy the model to a serverless GPU endpoint (e.g., HuggingFace Inference Endpoints, Modal, Replicate) and have FastAPI act as a proxy.

#### Bypassing or Adapting to API Rate Limits ('Hard' Stack)
*   **Risk**: The official Twitter/X API has strict rate limits for free tiers. Unofficial scrapers (snscrape) face IP bans and frequent breakage due to DOM changes.
*   **Mitigation**:
    1.  **Graceful Degradation**: Implement fallback mechanisms in FastAPI. If the scraper fails or rate-limits, fall back to analyzing a static, pre-downloaded dataset to ensure the demo always works.
    2.  **Proxy Rotation**: Use rotating residential proxies (e.g., BrightData, ScraperAPI) if using unofficial scraping.
    3.  **Caching**: Aggressively cache scraped results in Redis or SQLite based on the query, so identical searches don't trigger new scrapes.

#### Managing Class Imbalance in Datasets (Both Stacks)
*   **Risk**: Misinformation datasets often have far more "real" news than "fake" news, causing models to predict the majority class and appear highly accurate while failing to detect actual misinformation.
*   **Mitigation**:
    1.  **Algorithm Level**: Use class weights (`class_weight='balanced'` in Scikit-learn) to penalize the model more heavily for misclassifying the minority class.
    2.  **Data Level**: Apply Synthetic Minority Over-sampling Technique (SMOTE) to generate synthetic examples of the minority class, or randomly undersample the majority class.
    3.  **Evaluation Metrics**: Do not use standard Accuracy. Use F1-Score, Precision, Recall, and plot a Confusion Matrix to prove to graders that the model is genuinely learning to detect the minority class.

## Implementation Recommendations

### Quick Start Guide
1.  **Repository Setup**: Create a monorepo with `/frontend` (React) and `/backend` (FastAPI).
2.  **Safe Stack First**: Build the manual input UI and connect it to a dummy FastAPI endpoint returning random scores.
3.  **ML Integration**: Train a TF-IDF + Logistic Regression model in a notebook, export it with `joblib`, and load it into FastAPI.
4.  **Hard Stack Evolution (Optional)**: Branch the project. Replace the dummy text input with a scraping function, and swap the `joblib` model for a HuggingFace pipeline.

### Common Pitfalls
*   **Over-promising on the Hard Stack**: Web scraping is notoriously brittle. Do not rely entirely on live scraping for your final presentation. Always have a recorded video or a fallback to static data.
*   **Ignoring CORS**: React running on `localhost:3000` will be blocked from calling FastAPI on `localhost:8000` by default. Use `CORSMiddleware` in FastAPI.

### A. Glossary
*   **TF-IDF**: A statistical measure evaluating how relevant a word is to a document in a collection.
*   **Scraping**: Automated extraction of data from websites.
*   **Quantization**: Reducing the precision of model weights (e.g., 32-bit float to 8-bit integer) to save memory.
